# Advanced Wafer Defect Intelligence and Root-Cause Prediction Platform

A real FastAPI + React engineering platform for wafer-process defect intelligence.

## What is included

- FastAPI REST backend
- SQLite persistence for predictions and engineer feedback
- Random Forest defect classifier
- Isolation Forest novelty detector
- Saved preprocessing artifacts
- Model-based probable root-cause screening
- Model-based what-if analysis
- Engineer feedback workflow: PENDING → VALIDATED
- Lightweight model registry
- Controlled candidate retraining endpoint
- React + TypeScript + Vite engineering console
- No hardcoded prediction responses

## Important data note

If `backend/data/semiconductor_wafer_defect_dataset.csv` does not exist, the first backend startup creates a **clearly marked synthetic demo dataset** so the application can be exercised. These demo metrics are not representative of a real semiconductor dataset.

For your actual project, replace that CSV with the real dataset and retrain:

```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m training.train_defect_model
python -m uvicorn main:app --reload
```

Required columns for the baseline trainer:

```text
temperature_c
pressure_torr
gas_flow_sccm
etch_rate_nm_min
voltage_v
current_ma
process_step
defect_label
```

The application validates the actual process-step categories from the saved encoder rather than hardcoding an integer mapping.

## Run backend

```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Swagger: http://127.0.0.1:8000/docs

## Run frontend

Open another PowerShell window:

```powershell
cd frontend
npm install
npm run dev
```

Frontend: http://localhost:5173

Optional `.env`:

```text
VITE_API_BASE_URL=http://127.0.0.1:8000
```

## Important limitations

- Unknown-defect performance requires a genuinely supported unknown-class evaluation dataset. The baseline detector is calibrated against a validation score distribution, but it does not fabricate an unknown-defect F1.
- Root-cause screening in this starter project is transparent engineering interpretation based on configured reference distributions, not a trained causal model. It is explicitly labelled probable/model-based.
- Production drift metrics require reference and current production batches. The UI therefore reports `NOT_CONFIGURED` rather than inventing drift results.
- Image/wafer-map multimodal prediction is intentionally not enabled without valid paired image/process data.
- Candidate retraining is not automatically promoted to production.
